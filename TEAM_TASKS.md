## 0. Главное за 30 секунд

**Цель:** показать полный процесс — импорт → оценка по настраиваемому чек-листу → клик по доказательству →
апелляция → решение проверяющего → пересчитанный итог. **Новый критерий через UI, без правки кода.**

**Три вещи, которые жюри проверит обязательно:**
1. Организаторы заменят критерий → сохраняем новый чек-лист через UI и применяем к выданным диалогам.
2. Каждая оценка открывает реплику-доказательство (или проверенный диапазон для пропущенного действия), N/A с причиной.
3. Апелляция сохраняет исходник ИИ, а решение проверяющего корректно меняет итог.

**🚨 Блокер №1:** отдельного PDF чек-листа (8 критериев, веса, шкалы, N/A, грубые ошибки, округление) у нас **нет**.
Участник 4 запрашивает его у организаторов **сразу**. Сейчас в базе — ДЕМО-чек-лист, он не официальный.

**Ключевые даты:** T+1 контракт · T+5 первая настоящая оценка в UI · T+12 оба процесса работают ·
T+18 все P0 приняты · **T+23 контрольный набор** · **T+24 стоп-код (последний commit)**.

## 2. Общие правила работы

- **Ветки:** у каждого своя (`p1-backend`, `p2-ai`, `p3-ui`, `p4-rules`). В `main` сливает Участник 1 после проверки.
- **Свои файлы:** правите только свою зону (таблица ниже). `models.py` ↔ `frontend/js/api.js` меняются **согласованно**: 1 публикует → 3 синхронизирует → 2 и 4 проверяют.
- **Задача передана**, когда есть: commit, список файлов, как запустить, результат проверки, известные ограничения.
- **Статус «готово»** ставит Участник 4 после наблюдаемого результата в общей версии.
- **Секреты:** ключи, подписанные ссылки API/аудио, реальные транскрипты и БД — только в `.env`/`data/`, в Git не попадают.
- **Не добавляем:** регистрацию, CRM-интеграцию, векторную БД, своё распознавание речи, микросервисы.
- **Синки (5 мин):** T+1, T+3, T+5, T+8, T+12, T+18, T+22 — что работает / что блокирует / что передаём.
- Чужой код (ZIP другой команды) поверх проекта **не копировать**; брать только идеи.
